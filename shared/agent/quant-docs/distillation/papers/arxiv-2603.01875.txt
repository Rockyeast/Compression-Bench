A     Experimental Setup Details
A.1    Off-Policy Distillation
Models and Data. We randomly sample 100,000
instruction-following prompts from LMSys-Chat-
1M (Zheng et al., 2023) and generate responses
with Qwen3-14B. The loss validation, down-
stream performance, and efficiency experiments
use Qwen3-14B, Qwen3-32B, and Qwen3-30B-
A3B as teachers and Qwen3-4B and Qwen3-1.7B
as students (Yang et al., 2025). The cross-tokenizer
experiment uses Qwen3-14B as the teacher and
Llama3.2-3B as the student. For AlpacaEval 2.0,
we use Qwen3-235B-2507-Instruct as the evaluator
model.
Baselines and Configuration. We compare KD-
Flow with TRL (von Werra et al., 2020), ROLL
(Wang et al., 2025b), and MS-SWIFT (Zhao et al.,
2025). The efficiency experiments use a global
batch size of 128, gradient accumulation of 8, and a
maximum sequence length of 4,096. All off-policy
experiments run on one server with 8 NVIDIA H20
GPUs and CUDA 12.9.

A.2    On-Policy Distillation
Models and Data. We use DAPO-Math-17K (Yu
et al., 2025) and evaluate two teacher–student con-
figurations: Qwen3-14B → Qwen3-1.7B-Base and
JustRL-DeepSeek-1.5B → DeepSeek-R1-Distill-
1.5B.
Training Configuration. The maximum input
and generation lengths are 1,024 and 7,168, respec-
tively; each rollout batch contains 64 prompts and
four sampled responses per prompt. All frame-
works use the same dataset and generation settings,
with optimization hyperparameters matched where
supported.
Baselines and Hardware. We compare KDFlow
with verl (Sheng et al., 2025) and MS-SWIFT. The
efficiency comparison uses two identical 8-GPU
H20 nodes with CUDA 12.9: verl and MS-SWIFT
with PG-OPD allocate 8 GPUs each to the stu-
dent and teacher, whereas MS-SWIFT with GKD
and KDFlow colocate them over the shared 16
GPUs. The scalability experiments use the same
one-epoch workloads and generation settings on
one, two, four, and eight identical nodes.
